🐧 درس ۰۱: لینوکس چیست و چرا برنامه‌نویس‌ها باید یاد بگیرند

در این درس چه یاد می‌گیری؟

قبل از اینکه حتی یک دستور تایپ کنی، باید بدانی لینوکس چیست، چرا سرورهای دنیا روی آن می‌چرخند، و چرا یک برنامه‌نویس (حتی اگر فقط فرانت‌اند کار می‌کند) باید با آن راحت باشد.

  • تفاوت اساسی لینوکس با ویندوز از نگاه یک برنامه‌نویس
  • توزیع‌های رایج و اینکه کدام را برای چه کاری انتخاب کنی
  • مفهوم Kernel و Shell
  • چطور یک سرور راه‌دور را مدیریت می‌کنی

مفاهیم پایه

لینوکس یک سیستم‌عامل متن‌باز است که هسته‌ی آن (Kernel) توسط لینوس توروالدز در ۱۹۹۱ نوشته شد. امروز تقریباً تمام سرورهای وب، ابری (AWS، DigitalOcean، Hetzner)، کانتینرها و حتی اندروید روی لینوکس اجرا می‌شوند.

برای یک برنامه‌نویس، لینوکس یعنی:

  • محیطی که اپلیکیشن‌ات در آن واقعاً اجرا می‌شود (Production).
  • ابزاری قدرتمند برای اتوماسیون، دیپلوی و عیب‌یابی.
  • زبانی مشترک با تمام تیم DevOps و SysAdmin.

Kernel و Shell

Kernel هسته‌ی سیستم‌عامل است که با سخت‌افزار حرف می‌زند (حافظه، CPU، دیسک، شبکه). تو تقریباً هرگز مستقیم با آن کار نمی‌کنی.

Shell برنامه‌ای است که دستورهای تو را می‌گیرد و به Kernel می‌فرستد. رایج‌ترین Shell در سرورها bash است. وقتی SSH می‌زنی یا ترمینال باز می‌کنی، در واقع داخل یک Shell هستی.

چطور سرور راه‌دور را مدیریت می‌کنی؟

تقریباً همیشه از طریق SSH:

ssh user@192.168.1.50
# یا
ssh user@myserver.example.com

بعد از ورود، تمام کارها با خط فرمان انجام می‌شود. گرافیک روی سرور تولید معمولاً نصب نیست (Headless).

🐧 درس ۰۲: ترمینال، Shell و اولین دستورها

در این درس چه یاد می‌گیری؟

ترمینال خانه‌ی جدید توست. باید بدانی دستور چطور ساخته می‌شود، چطور کمک بگیری، و چطور تاریخچه‌ی دستورها را مدیریت کنی.

  • ساختار یک دستور لینوکس
  • کمک گرفتن با man و --help
  • تاریخچه، تکمیل خودکار و میانبرهای مفید
  • دستورهای اولیه‌ی روزمره

مفاهیم پایه

Shell برنامه‌ای است که خط فرمان را تفسیر می‌کند. روی تقریباً تمام سرورها bash پیش‌فرض است.

ساختار کلی هر دستور:

command [options] [arguments]
  • command: نام برنامه (مثل ls، cp)
  • options یا flags: تنظیمات رفتار (مثل -l یا --long)
  • arguments: ورودی‌ها (مسیر فایل، نام کاربر و ...)

مثال:

ls -lah /var/log
# ls     → دستور
# -lah   → گزینه‌ها (long, all, human-readable)
# /var/log → آرگومان (مسیر)
نکته: گزینه‌های کوتاه با یک خط تیره (-l) و گزینه‌های بلند با دو خط تیره (--all) نوشته می‌شوند.

کمک گرفتن

command --help     # خلاصه و سریع
man command        # راهنمای کامل (با q خارج شو)
info command       # گاهی جزئیات بیشتر

🐧 درس ۰۳: ساختار فایل‌سیستم لینوکس (FHS)

در این درس چه یاد می‌گیری؟

در لینوکس همه‌چیز فایل است. باید بدانی هر پوشه‌ی ریشه چه کاری می‌کند تا وقتی لاگ می‌خوانی یا کانفیگ تغییر می‌دهی گم نشوی.

  • استاندارد FHS و پوشه‌های اصلی
  • تفاوت مسیر مطلق و نسبی
  • معنی ~ و . و ..

مفاهیم پایه

فایل‌سیستم لینوکس از یک ریشه (/) شروع می‌شود و همه‌ی دیسک‌ها و پارتیشن‌ها زیر آن mount می‌شوند. برخلاف ویندوز که چند درایو (C:، D:) دارد، اینجا همه چیز زیر یک درخت واحد است.

مسیر مطلق و نسبی

  • ~ = خانه‌ی کاربر فعلی (/home/ali)
  • . = پوشه‌ی فعلی
  • .. = پوشه‌ی والد

ساخت، کپی، جابه‌جایی، حذف و پیدا کردن فایل‌ها — کارهای روزمره‌ای که هر روز انجام می‌دهی.

  • تمام فلگ‌های مهم ls
  • mkdir، cp، mv، rm به‌صورت ایمن
  • find — قوی‌ترین ابزار جست‌وجوی فایل

مفاهیم پایه

در لینوکس فایل و پوشه از نظر دستورها خیلی شبیه هم رفتار می‌کنند، اما بعضی فلگ‌ها مخصوص پوشه هستند (مثل -R برای بازگشتی).

هشدار: دستور rm -rf برگشت‌ناپذیر است. سطل آشغالی وجود ندارد. همیشه دو بار مسیر را چک کن.

💡 سناریوی واقعی

🎯 سناریو ۱: می‌خواهی تمام فایل‌های .log قدیمی‌تر از ۷ روز را پیدا و حذف کنی.

🔧 راه‌حل:

# اول فقط پیدا کن (بدون حذف)
find /var/log -name "*.log" -mtime +7

# اگر مطمئن شدی:
find /var/log -name "*.log" -mtime +7 -delete

📖 توضیح: -mtime +7 یعنی بیش از ۷ روز از آخرین تغییر گذشته. همیشه اول بدون -delete اجرا کن.

🎯 سناریو ۲: پروژه‌ات پر از node_modules شده و می‌خواهی همه‌شان را پیدا کنی.

🔧 راه‌حل:

find ~ -type d -name "node_modules"

⚠️ اشتباهات رایج

❌ اشتباه: rm -rf / یا rm -rf /*

✅ درست: هرگز این دستور را نزن. حتی به شوخی.

❌ اشتباه: cp -r src/* dest/ وقتی dest وجود ندارد.

✅ درست: اول mkdir dest کن یا از cp -r src dest استفاده کن.

❌ اشتباه: فراموش کردن -r هنگام کپی پوشه.

✅ درست: برای پوشه همیشه cp -r یا cp -a.

✏️ تمرین

  1. یک ساختار پوشه بساز: ~/projects/demo/{src,tests,docs}
  2. چند فایل خالی داخل src بساز و با ls -lah ببین.
  3. با find تمام فایل‌های .js داخل home را پیدا کن.
mkdir -p ~/projects/demo/{src,tests,docs}
touch ~/projects/demo/src/{index,app,utils}.js
ls -lah ~/projects/demo/src
find ~ -name "*.js" 2>/dev/null

📝 خلاصه‌ی درس

  • ls -lah دوست روزمره‌ات است.
  • find برای جست‌وجوی قدرتمند ضروری است.
  • rm -rf خطرناک است — همیشه مسیر را دوباره بخوان.

حالا می‌توانی فایل‌ها را مثل یک حرفه‌ای جابه‌جا کنی.

🐧 درس ۰۷: کاربران و گروه‌ها

در این درس چه یاد می‌گیری؟

چطور کاربر بسازی، به گروه اضافه کنی، و با sudo کار کنی — بدون اینکه همه‌چیز را با root خراب کنی.

  • root، sudo و تفاوت‌شان
  • ساخت و مدیریت کاربر و گروه
  • فایل‌های /etc/passwd و /etc/shadow

مفاهیم پایه

root کاربر فوق‌العاده است (UID=0). می‌تواند هر کاری بکند. برای کارهای روزمره از آن استفاده نکن.

sudo اجازه‌ی اجرای موقت دستور با دسترسی root را به کاربران مجاز می‌دهد.

هشدار: هرگز به‌صورت پیش‌فرض با root لاگین نکن. یک کاربر عادی بساز و او را به گروه sudo اضافه کن.

💡 سناریوی واقعی

🎯 سناریو: می‌خواهی یک کاربر به نام deploy بسازی که بتواند با sudo کار کند.

🔧 راه‌حل:

# تست:

⚠️ اشتباهات رایج

❌ اشتباه: کار کردن دائمی با root.

✅ درست: کاربر عادی + sudo.

❌ اشتباه: usermod -G به‌جای -aG (گروه‌های قبلی پاک می‌شوند).

✅ درست: همیشه -aG برای اضافه کردن به گروه.

✏️ تمرین

  1. یک کاربر آزمایشی بساز و به گروه sudo اضافه‌اش کن.
  2. با آن کاربر لاگین کن و یک دستور sudo اجرا کن.

📝 خلاصه‌ی درس

  • root را فقط وقتی لازم است استفاده کن.
  • adduser + usermod -aG sudo الگوی استاندارد است.

حالا می‌دانی چطور کاربر امن بسازی.

🐧 درس ۰۸: مجوزها (Permissions)

در این درس چه یاد می‌گیری؟

معنی rwx، چطور مجوز بدهی و هرگز 777 نکنی.

  • مجوز فایل و پوشه
  • chmod عددی و حرفی
  • chown و umask

مفاهیم پایه

هر فایل سه دسته‌ی مجوز دارد: صاحب (u)، گروه (g)، دیگران (o).

هر دسته سه مجوز: r (خواندن)، w (نوشتن)، x (اجرا).

عددمجوزمعنی برای فایلمعنی برای پوشه
4rخواندن محتوالیست کردن فایل‌ها
2wتغییر محتواساخت/حذف فایل داخل
1xاجراورود به پوشه (cd)

مثال رایج:

  • 644 → rw-r--r-- (فایل معمولی)
  • 755 → rwxr-xr-x (اسکریپت یا پوشه)
  • 600 → rw------- (فایل محرمانه مثل .env یا کلید SSH)
هشدار امنیتی: هرگز chmod 777 نکن. این یعنی همه می‌توانند بخوانند، بنویسند و اجرا کنند.

📌 دستورهای مهم این درس

💡 سناریوی واقعی

🎯 سناریو: فایل .env داری و می‌خواهی فقط خودت بتوانی آن را بخوانی.

🔧 راه‌حل:

ls -l .env

⚠️ اشتباهات رایج

❌ اشتباه: chmod 777 -R /var/www

✅ درست: مجوزهای حداقلی لازم را بده (معمولاً 755 برای پوشه و 644 برای فایل).

❌ اشتباه: فراموش کردن x برای پوشه‌ها.

✅ درست: بدون x نمی‌توانی وارد پوشه شوی حتی اگر r داشته باشی.

✏️ تمرین

  1. یک فایل بساز و مجوز آن را 600 کن.
  2. یک اسکریپت بساز و آن را قابل اجرا کن (chmod +x).

📝 خلاصه‌ی درس

  • 644 برای فایل، 755 برای پوشه/اسکریپت، 600 برای اسرار.
  • هرگز 777.
  • chown برای تغییر مالکیت.

مجوزها اولین خط دفاعی تو هستند.

🐧 درس ۰۹: SSH و اتصال امن به سرور

در این درس چه یاد می‌گیری؟

اتصال امن، انتقال فایل و قفل کردن SSH تا فقط با کلید وارد شوی.

  • ssh، scp، rsync
  • تولید و کپی کلید
  • سخت‌سازی SSH

مفاهیم پایه

SSH (Secure Shell) پروتکل استاندارد اتصال امن به سرور است. دو روش احراز هویت دارد: رمز عبور و کلید عمومی/خصوصی. روش کلید بسیار امن‌تر است.

💡 سناریوی واقعی

🎯 سناریو: می‌خواهی بدون رمز به سرور وصل شوی و فایل‌ها را همگام کنی.

🔧 راه‌حل:

ssh-copy-id deploy@server
rsync -avz --progress ./dist/ deploy@server:/var/www/myapp/

⚠️ اشتباهات رایج

❌ اشتباه: گذاشتن کلید خصوصی روی سرور یا در گیت.

✅ درست: کلید خصوصی فقط روی ماشین خودت بماند (مجوز 600).

❌ اشتباه: باز گذاشتن پورت ۲۲ با رمز عبور روی اینترنت.

✅ درست: فقط کلید + در صورت امکان تغییر پورت + fail2ban.

✏️ تمرین

  1. یک کلید ed25519 بساز.
  2. با scp یک فایل به سرور بفرست (اگر سرور داری).

📝 خلاصه‌ی درس

  • همیشه از کلید SSH استفاده کن، نه رمز.
  • rsync بهترین ابزار همگام‌سازی است.
  • sshd_config را سخت‌سازی کن.

حالا می‌توانی امن به سرور وصل شوی.

بخش سوم: پروسه‌ها و منابع سیستم

🐧 درس ۱۰: پروسه‌ها (Processes)

در این درس چه یاد می‌گیری؟

دیدن، متوقف کردن و مدیریت پروسه‌ها — و اجرای برنامه‌های طولانی با tmux.

  • ps، top، htop
  • kill و سیگنال‌ها
  • jobs، nohup، tmux، screen

مفاهیم پایه

هر برنامه‌ی در حال اجرا یک یا چند پروسه است و یک PID منحصربه‌فرد دارد. سیگنال‌ها راه ارتباط با پروسه‌ها هستند:

  • SIGTERM (15): درخواست توقف مؤدبانه (پیش‌فرض kill)
  • SIGKILL (9): کشتن اجباری (پروسه‌ نمی‌تواند نادیده بگیرد)
  • SIGHUP (1): اغلب برای reload تنظیمات

✅ درست: tmux برای کار دستی، systemd برای سرویس دائمی.

❌ اشتباه: همیشه kill -9.

✅ درست: اول kill (SIGTERM)، اگر جواب نداد kill -9.

✏️ تمرین

  1. با ps تمام پروسه‌های مربوط به bash را پیدا کن.
  2. یک نشست tmux بساز، دستوری اجرا کن، detach کن و دوباره attach کن.

📝 خلاصه‌ی درس

  • ps و top برای دیدن، kill برای متوقف کردن.
  • tmux برای نگه‌داشتن نشست‌های طولانی ضروری است.
